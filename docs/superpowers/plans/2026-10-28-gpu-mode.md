# GPU Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Omarchy plugin `sviat.gpu-mode` that switches Eco / Standard / Ultimate through supergfxd from a G-Helper-style window, with a single reboot per switch.

**Architecture:**
- One Python stdlib program, `libexec/gpu-mode`:
  - `state` runs as the user and prints JSON for the UI;
  - `apply <mode>` runs as root through pkexec, writes the MUX, `/etc/supergfxd.conf` and the Eco-only files, and rolls back on failure;
  - `normalize` is a root, install-time fix for a stale config.
- A root-owned copy plus a polkit action is the only privileged path.
- QML: a summoned `panel` (the window), an optional `bar-widget`, and a pure `Model.js`.
- A user-level installer links the plugin and rewrites the Omarchy menu row.

**Tech Stack:** Python 3 stdlib, QML/Quickshell (Omarchy 4.0.6 shell, `qs.Commons`, `qs.Ui`), bash, polkit/pkexec, supergfxd 5.2.7, Node `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-28-gpu-mode-design.md` (approved 2026-10-28). Read it first; this plan does not repeat its facts or reasons.

## Global Constraints

- Local only: no git remote, no push. Work on branch `dev`; never commit to `main`.
- Commits are authored by the user, with no assistant attribution.
- English for UI strings, code comments and the README. Comments follow the user's global rules: default none, only the "why".
- Plugin id `sviat.gpu-mode`; repo `~/Projects/omarchy-gpu-mode`; plugin dir `~/.config/omarchy/plugins/sviat.gpu-mode` is a symlink to the repo.
- Modes map exactly: `eco` → `Integrated`, `standard` → `Hybrid`, `ultimate` → `AsusMuxDgpu`. MUX `1` = Optimus, `0` = dGPU.
- Never call `supergfxctl -m` outside the sleep hook. Never use asusd for GPU state.
- The root helper runs only from `/usr/local/libexec/omarchy-gpu-mode/gpu-mode`, owned by root, mode 0755. It reads no environment variables and no files from the plugin dir.
- Every switch is followed immediately by `omarchy-system-reboot`. There is no "apply later".
- Machine facts (NVIDIA card, connectors, MUX path) are detected at runtime: PCI vendor `0x10de`, class `0x03*`.
- Python is run as `python3 -I` in every shebang and test command.

## Review Focus

1. **supergfxd hung or stopped:** `state` still answers within ~4 s, deriving the mode from sysfs, and the window opens. Task 1 test `test_state_without_supergfxctl`.
2. **`/etc/supergfxd.conf` missing, unreadable or invalid JSON:** `apply` writes nothing at all (MUX included) and exits 1 with a message. Task 2 test `test_apply_refuses_bad_conf_without_side_effects`.
3. **Polkit dialog dismissed** (pkexec exit 126 or 127): no error banner, the buttons are re-enabled, no reboot. Task 4 test `classifyHelperExit treats 126/127 as dismissed`.
4. **Apply activated twice** (double Enter or double click): exactly one helper run. Task 4 test `applyGuard blocks a second apply while busy`; the panel in Task 5 wires it.
5. **Root helper missing, or older than the repo copy:** the window shows the install command instead of failing at apply time. Task 1 test `test_state_reports_helper_status`; Task 4 test `viewFor shows helper banners`.

**Interfaces:**
- Produces, in `libexec/gpu-mode`:
  - `MODES = {"eco": "Integrated", "standard": "Hybrid", "ultimate": "AsusMuxDgpu"}`
  - `class Root(base="/")` with `p(abs_path: str) -> pathlib.Path`
  - `read_conf(root) -> dict`, raising `ConfError(str)`
  - `mux_path(root) -> Path | None`: armoury `…/gpu_mux_mode/current_value` first, then `/sys/devices/platform/asus-nb-wmi/gpu_mux_mode`
  - `read_mux(root) -> int | None`
  - `mux_pending(root) -> bool`: armoury `pending_reboot == "1"`
  - `dgpu_disabled(root) -> bool | None`
  - `nvidia_card(root) -> str | None`, for example `"card1"`
  - `external_connected(root) -> list[str]`: connector names such as `"HDMI-A-1"`, eDP excluded, `status == "connected"` only
  - `runtime_mode(timeout: float = 3.0) -> str | None`: `/usr/bin/supergfxctl -g`; `None` on timeout or error
  - `derive_state(conf_mode: str | None, mux: int | None, runtime: str | None, nvidia_present: bool, pending: bool) -> dict` with keys `active`, `configured`, `inconsistent`
  - `helper_status(repo_file: Path, installed: Path) -> str`: `"missing" | "outdated" | "current"`, by byte equality
  - `state(root, runtime: str | None, repo_file: Path) -> dict`: the JSON contract below
  - `main(argv: list[str]) -> int`
- JSON contract of `gpu-mode state` (one line on stdout, exit 0 even on errors):
  `{"version":1,"active":"eco|standard|ultimate","configured":"eco|standard|ultimate|unknown","inconsistent":bool,"mux":0|1|null,"muxPendingReboot":bool,"dgpuDisabled":bool|null,"externalConnected":[str],"stockHookPresent":bool,"helper":"missing|outdated|current","error":str}`

### Task 2: The `apply` and `normalize` commands, with the Eco boot/sleep files

**Files:**
- Modify: `libexec/gpu-mode`
- Test: `tests/test_apply.py`

**Interfaces:**
- Consumes: everything from Task 1.
- Produces:
  - `target_config(conf: dict, mode: str) -> dict`: sets `mode`; for `eco` also `vfio_enable: True`; all other keys are kept unchanged.
  - `apply_mode(root, mode: str, reload=lambda: None) -> None`, raising `ApplyError(str)`.
  - `normalize(root) -> bool`: if the conf says `AsusMuxDgpu` while the MUX is `1`, rewrite it to `Hybrid` and return `True`.
  - `HOOK_PATH = "/usr/lib/systemd/system-sleep/omarchy-gpu-mode-igpu"`, `DROPIN_PATH = "/etc/systemd/system/supergfxd.service.d/delay-start.conf"`, `STOCK_HOOK_PATH = "/usr/lib/systemd/system-sleep/force-igpu"`.
  - `HOOK_SOURCE: str`, `DROPIN_SOURCE: str`: file contents embedded in the script.
  - `main(["apply", mode])`: refuses unless `os.geteuid() == 0` and `mode in MODES`; exit 0 on success, 1 with a one-line stderr message on failure, 2 on usage. `main(["normalize"])` requires root.
  - `reload` in `main` is `systemctl daemon-reload`.

- [ ] **Step 1: Write failing tests in `tests/test_apply.py`** (fake root from `tests/fakeroot.py`)
  - `test_standard_to_eco`:
    - conf mode becomes `Integrated` and `vfio_enable` becomes `True`; `hotplug_type` and the other keys are untouched;
    - the MUX file still reads `1`;
    - the hook and the drop-in exist with mode 0755/0644 and the contents `HOOK_SOURCE`/`DROPIN_SOURCE`;
    - the stock `force-igpu` is removed if present;
    - `reload` was called.
  - `test_eco_to_ultimate`: conf `AsusMuxDgpu`, MUX file `0`, hook and drop-in removed.
  - `test_ultimate_to_eco_single_step`: starting from MUX `0`, conf `AsusMuxDgpu` → MUX `1`, conf `Integrated`, Eco files present.
  - `test_ultimate_refused_when_dgpu_disabled`: `dgpu_disable` = `1` → `ApplyError`, nothing changed.
  - `test_apply_refuses_bad_conf_without_side_effects`: invalid conf JSON, or a missing conf → `ApplyError`, and the MUX, hook and drop-in are byte-identical to before.
  - `test_rollback_on_failure`: make the conf directory read-only after the MUX write (or inject a failing writer) → `ApplyError`; the MUX, conf and Eco files are restored to their previous state.
  - `test_idempotent`: applying the active mode twice leaves identical bytes.
  - `test_main_rejects_args`: `main(["apply", "turbo"]) == 2`, `main(["apply"]) == 2`, `main(["rm", "-rf"]) == 2`.
  - `test_normalize`: the stale conf becomes `Hybrid`; a consistent conf is left alone (returns `False`, same bytes).
- [ ] **Step 2: Run** `python3 -I tests/test_apply.py`. Expected: FAIL.
- [ ] **Step 3: Implement.**
  - Order: read and validate the conf → snapshot (conf bytes, MUX, the three Eco-file states) → write the MUX if it differs → install or remove the Eco files → write the conf atomically (`tempfile` in the same dir, `os.replace`, mode 0644) → `reload()` if the drop-in changed.

  - `HOOK_SOURCE` is bash adapted from Omarchy's `default/systemd/system-sleep/force-igpu`, with a one-line attribution comment.

    - It keeps the stock pre/post logic: a Vfio switch before hibernate, then Vfio→Integrated after resume with the 4 s settle, and uses absolute paths.
